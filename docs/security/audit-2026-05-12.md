# moer-booking 백엔드 보안 감사 보고서

- **작성일**: 2026-05-12
- **대상**: `C:\Project\moer-booking` 전체 백엔드 소스 (43개 컨트롤러, MyBatis XML, 설정 파일, Docker 구성)

- **분석 방식**: 5개 영역 병렬 정적 분석 + 핵심 항목 수작업 검증

| 위험도 | 건수 | 런칭 차단 여부 |
|--------|------|----------------|
| Critical | 7 | **차단 (Blocker)** |
| High | 11 | 차단 |

| Low | 4 | 백로그 |

**런칭 전 반드시 해결해야 할 Critical 항목**:
1. `application.yml`, `docker-compose.yml`에 평문으로 커밋된 DB/OAuth/SMTP/JWT 시크릿
2. MyBatis XML에서 `${}` 문자열 치환에 의한 SQL Injection 가능 지점 (3곳)
3. `UserController` 전체에 권한 검증 부재 (IDOR, 사용자 열거)
4. 파일 삭제 경로에 path normalize 부재 (Path Traversal)
5. Refresh Token 평문 저장, 회전(rotation) 미구현
6. HTTP 보안 헤더(HSTS / X-Frame-Options / CSP 등) 전무
7. 인증 엔드포인트에 Rate Limiting 없음 (Brute-force 무방비)

## 2. Critical 발견 사항

### C-01. 운영 시크릿이 소스코드에 평문 커밋
- **파일**: `src/main/resources/application.yml:9`, `36-37`, `55-74`, `115`; `docker-compose.yml:11-12`
- **내용**:
  - DB 비밀번호 `moer2026@` (환경변수 처리도 안 됨, 그냥 평문)
  - SMTP 비밀번호 `${MAIL_PASSWORD:U3SXTOXHzkPX}` — 기본값이 실제 비밀번호
  - Google/Naver/Kakao OAuth Client Secret 모두 기본값에 실제 키 노출
  - JWT 시크릿 기본값 `moer-booking-system-secret-key-change-this-in-production-minimum-256-bits` (예측 가능)
  - `.gitignore`에 `application-prod.yml`은 있으나 `application.yml`은 추적됨 → git 이력에 영구 저장됨
- **공격 시나리오**: 저장소 노출 즉시 DB 완전 침해, 사용자 OAuth 토큰 가로채기, 모든 사용자 JWT 위조 가능
- **OWASP**: A02 Cryptographic Failures, A05 Security Misconfiguration

### C-02. SQL Injection — 동적 컬럼명 치환
- **파일**: `src/main/resources/mapper/business/BusinessSettingsMapper.xml:164`
- **내용**: `SET ${column} = #{value}` — 컬럼명이 사용자 입력으로 들어옴
- **공격 시나리오**: `column=onboarding_completed, password='hacked' WHERE 1=1 --` 형태 주입 시 임의 컬럼 변조
- **확인 필요**: 호출 측 Service에서 컬럼명을 화이트리스트로 검증하는지 (현재 미확인 → **별도 검증 필요**)
- **OWASP**: A03 Injection

### C-03. SQL Injection — INTERVAL 인자 문자열 치환
- **파일**: `src/main/resources/mapper/customer/CustomerMapper.xml:222`, `244`
- **내용**: `INTERVAL '${monthsAgo} months'` — 정수형 파라미터를 문자열 치환으로 처리
- **공격 시나리오**: API에서 `monthsAgo` 파라미터가 사용자 입력과 연결될 경우 `'1 months'; DELETE FROM customers; --` 주입 가능
- **OWASP**: A03 Injection

### C-04. UserController 권한 검증 전무
- **파일**: `src/main/java/io/moer/booking/domain/user/controller/UserController.java` 전체
- **문제**:
  - 클래스/메서드에 `@PreAuthorize` 어노테이션 0개
  - `GET /api/users` (전체 사용자 목록), `GET /api/users/{userId}` (임의 ID 조회), `GET /api/users/email/{email}` (이메일로 조회), `GET /api/users/search` 모두 `authenticated()` 수준만 보호됨
  - `GET /api/users/check-email`은 인증조차 불필요 — 이메일 존재 여부 무제한 확인 가능
  - `PATCH /api/users/{userId}` 본인 확인 로직 없음 → **IDOR 가능**
- **공격 시나리오**: 평범한 CUSTOMER 토큰만으로 전체 OWNER/STAFF 이메일 수집 → 표적 피싱 / 다른 사용자 정보 변조
- **OWASP**: A01 Broken Access Control

### C-05. Path Traversal — 파일 삭제
- **파일**: `src/main/java/io/moer/booking/common/storage/LocalFileStorageService.java:91-92`
- **내용**:
  ```java
  String relativePath = fileUrl.replaceFirst("^/uploads/", "");
  Path filePath = Paths.get(uploadDir, relativePath);  // normalize 검증 없음
  Files.delete(filePath);
  ```
- **공격 시나리오**: 리뷰/포트폴리오 삭제 API 호출 시 `fileUrl=/uploads/../../config/secrets.yml` 입력하면 업로드 디렉토리 외부 파일 삭제 가능
- **개선**: `filePath.normalize().toRealPath()`로 정규화 후 `uploadDir` 하위인지 검증
- **OWASP**: A01 Broken Access Control

### C-06. Refresh Token 평문 저장 + Rotation 부재
- **파일**: `src/main/java/io/moer/booking/domain/auth/service/AuthService.java` (라인 120-143 부근)
- **문제**:
  - Refresh Token이 DB에 평문 저장
  - 갱신(refresh) 시 동일 토큰 재사용 — 탈취 탐지 불가능
  - 로그아웃 전까지 7일간 무한정 유효
- **공격 시나리오**: 브라우저 메모리/localStorage/네트워크 스니핑으로 탈취 후 7일간 계정 점유, 정상 사용자는 인지 불가
- **OWASP**: A07 Identification & Authentication Failures

### C-07. HTTP 보안 헤더 전무
- **파일**: `src/main/java/io/moer/booking/common/config/SecurityConfig.java:82-137`
- **누락 헤더**: `Strict-Transport-Security`, `X-Frame-Options`, `X-Content-Type-Options`, `Content-Security-Policy`, `Referrer-Policy`, `Permissions-Policy`
- **공격 시나리오**: Swagger UI Clickjacking, MIME 스니핑을 통한 XSS, HTTPS 다운그레이드 공격
- **OWASP**: A05 Security Misconfiguration

## 3. High 위험 발견 사항

### H-01. Swagger UI / API Docs 프로덕션 무제한 노출
- **파일**: `SecurityConfig.java:105-111`, `SwaggerConfig.java:65-68`
- 모든 환경에서 `permitAll()`, 테스트 계정(`admin@moer.io / password123`)이 문서에 하드코딩

### H-02. Rate Limiting 부재
- **파일**: `AuthController`, `UserController#checkEmailDuplicate`, `PublicReviewController`, `PublicBookingController`
- 로그인/비밀번호 재설정/이메일 확인/공개 검색 API 모두 무제한 호출 가능
- 현재 `InquiryService:82-97`의 IP당 시간당 5건 제한만 유일한 방어

### H-03. JWT 시크릿 256비트 미만 + 환경변수 강제 부재
- **파일**: `JwtProperties.java:13`, `application.yml:115`
- 기본 시크릿 길이가 ASCII 약 74자(약 592비트로 표면적으로는 충분하나 예측 가능) — 핵심은 **소스에 노출된 시점에서 무효**
- 환경변수 미설정 시에도 기본값으로 동작 → CI/CD에서 강제 검증 없음

### H-04. Dashboard / Business 데이터 접근 통제 불일치
- **파일**: `DashboardController.java:30-36`, `BusinessController.java`
- `canAccessBusiness()` 호출 후 반환값을 확인하지 않거나, 매장 목록 조회 시 사용자 소속 매장으로 필터링하지 않음
- OWNER A가 OWNER B의 매출/예약 통계 조회 가능성

### H-05. LIKE 검색 와일드카드 이스케이프 부재
- **파일**: `src/main/resources/mapper/business/BusinessMapper.xml:149`, `314` 등
- `LIKE '%' || #{keyword} || '%'` — 사용자가 `%`, `_` 입력 시 전체 결과 반환 (정보 노출 또는 DoS)

### H-06. XSS — 사용자 입력 미정제 응답 반환
- **파일**: `CustomerReviewController.java:107-120` (리뷰 content), `InquiryService` (문의 content 5000자 길이만 검증), 매장 설명 텍스트
- 응답 시점 HTML escape 없음 → 프론트가 `dangerouslySetInnerHTML` 등 부주의하면 즉시 stored XSS

### H-07. 파일 업로드 — originalFilename 저장 및 노출
- **파일**: `ReviewService.java:290`
- 사용자 디바이스의 경로 정보 노출 (`C:\Users\xxx\photo.jpg` 패턴)

### H-08. PII 평문 로그 출력
- **파일**: `PublicBookingService.java:413, 565`, `CustomerService.java:79, 287, 293, 305`, `InquiryService.java:43`, `NotificationService.java:189`
- 전화번호, 이메일, 고객명이 `log.info(...)`로 기록 — 로그 수집 시스템에서 PII 유출 → 개인정보보호법(PIPA) 위반 소지

### H-09. CORS `allowedHeaders: "*"`
- **파일**: `SecurityConfig.java:72`
- 화이트리스트(`Authorization, Content-Type, Accept`)로 좁힐 필요. `allowCredentials: true`와 wildcard 조합은 위험 가중

### H-10. 로그인 실패 횟수 제한 / 계정 잠금 부재
- **파일**: `AuthService.java:72-115`
- 무제한 시도 가능 → CUSTOMER 약한 비밀번호 무차별 공격

### H-11. PaymentResponse — pgTransactionId 노출
- **파일**: `src/main/java/io/moer/booking/domain/payment/dto/PaymentResponse.java`
- PG사 거래번호는 환불/위변조 공격 표적이 됨 — 권한별 마스킹 필요

## 6. 양호한 점 (참고)

- `GlobalExceptionHandler`가 스택 트레이스 미노출
- 비밀번호 재설정 시 미등록 이메일도 동일 응답 반환 (사용자 열거 부분 방지)
- Refresh Token 만료 검증, 로그아웃 시 삭제 처리 존재
- 비밀번호 해싱 자체는 BCrypt 사용 (강도만 부족)
- SMTP STARTTLS 강제 설정
- 회원 탈퇴는 soft delete + 감사 로그 기록
