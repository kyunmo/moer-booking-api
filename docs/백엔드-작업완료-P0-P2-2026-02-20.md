## 1. [P1-1] 예약 시간 충돌 검증 API

### 1.1 직원 가용 시간 확인 API (신규)

```
GET /api/businesses/{businessId}/reservations/availability
```

**Query Parameters:**

| 파라미터 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| staffId | Long | Y | 직원 ID |
| date | String (yyyy-MM-dd) | Y | 예약 날짜 |
| startTime | String (HH:mm) | Y | 시작 시간 |
| endTime | String (HH:mm) | Y | 종료 시간 |
| excludeReservationId | Long | N | 수정 시 현재 예약 제외 |

**Response (200, 가용):**
```json
{
  "success": true,
  "data": {
    "available": true,
    "conflicts": []
  }
}
```

**Response (200, 충돌):**
```json
{
  "success": true,
  "data": {
    "available": false,
    "conflicts": [
      {
        "reservationId": 123,
        "customerName": "홍길동",
        "startTime": "14:00",
        "endTime": "15:00",
        "serviceName": "커트, 펌"
      }
    ]
  }
}
```

### 1.2 서버 측 검증 (기존 유지)

- `POST /api/businesses/{businessId}/reservations` (예약 생성) - 시간 충돌 시 에러
- `PATCH /api/businesses/{businessId}/reservations/{id}` (예약 수정) - 시간 충돌 시 에러
- 기존 `validateReservation()` 로직이 이미 시간 충돌을 검증하고 있었음
- 충돌 시 에러코드: `C001` (기존 INVALID_INPUT_VALUE 활용, 메시지에 충돌 상세 포함)

### 1.3 FE 연동 가이드

```javascript
// 시간 선택 후 가용성 확인
const checkAvailability = async (businessId, staffId, date, startTime, endTime) => {
  const params = new URLSearchParams({ staffId, date, startTime, endTime });
  const res = await api.get(`/businesses/${businessId}/reservations/availability?${params}`);
  return res.data; // { available: true/false, conflicts: [...] }
};

// 예약 수정 시 현재 예약 제외
const checkForEdit = async (businessId, staffId, date, startTime, endTime, reservationId) => {
  const params = new URLSearchParams({ staffId, date, startTime, endTime, excludeReservationId: reservationId });
  const res = await api.get(`/businesses/${businessId}/reservations/availability?${params}`);
  return res.data;
};
```

## 2. [P2-2] 다중 예약 일괄 상태 변경 API (신규)

```
PATCH /api/businesses/{businessId}/reservations/bulk-status
```

**Request Body:**
```json
{
  "reservationIds": [1, 2, 3, 5],
  "status": "CONFIRMED"
}
```

**허용 상태 전이:**
- `PENDING` -> `CONFIRMED` (일괄 확정)
- `CONFIRMED` -> `COMPLETED` (일괄 완료)
- `PENDING` / `CONFIRMED` -> `CANCELLED` (일괄 취소)

**Response (200):**
```json
{
  "success": true,
  "data": {
    "success": [1, 2, 3],
    "failed": [
      {
        "reservationId": 5,
        "reason": "이미 취소되거나 완료된 예약입니다 (현재: CANCELLED)"
      }
    ]
  }
}
```

**비즈니스 로직:**
- COMPLETED 변경 시: 고객 통계(visitCount, totalSpent) 자동 업데이트 + CustomerHistory 자동 생성
- CANCELLED 변경 시: 취소 사유 "일괄 취소" 자동 기록 + 예약 수 감소
- 개별 예약별 독립 처리 (하나 실패해도 나머지 정상 처리)

### FE 연동 가이드

```javascript
// 예약 목록에서 체크박스 선택 후 일괄 변경
const bulkStatusChange = async (businessId, reservationIds, status) => {
  const res = await api.patch(`/businesses/${businessId}/reservations/bulk-status`, {
    reservationIds,
    status
  });
  const { success, failed } = res.data;

  if (failed.length > 0) {
    // 부분 실패 알림 표시
    failed.forEach(f => showWarning(`예약 #${f.reservationId}: ${f.reason}`));
  }
  if (success.length > 0) {
    showSuccess(`${success.length}건 처리 완료`);
  }
};
```

## 3. [P2-4] 재예약용 이전 예약 조회

### 변경 사항

기존 `GET /api/customer/reservations/{reservationNumber}` 응답에 `staffId` 필드 추가.

**기존 응답에 포함되어 있던 정보:**
- `services` - 서비스 목록 (id, name, price, duration)
- `staffName` - 담당 스태프 이름
- `businessSlug` - 매장 슬러그 (예약 페이지 URL 구성용)

**새로 추가된 필드:**
- `staffId` (Long) - 담당 스태프 ID (재예약 시 스태프 자동 선택용)

**추가 API 불필요:** 기존 API가 재예약에 필요한 모든 정보를 제공합니다.

### FE 연동 가이드

```javascript
// 재예약 버튼 클릭 시
const handleRebook = async (reservationNumber) => {
  const res = await api.get(`/customer/reservations/${reservationNumber}`);
  const prevReservation = res.data;

  // 예약 페이지로 이동 시 이전 예약 정보 전달
  router.push({
    path: `/booking/${prevReservation.businessSlug}/reserve`,
    query: {
      staffId: prevReservation.staffId,
      serviceIds: prevReservation.services.map(s => s.id).join(',')
    }
  });
};
```

## 4. [P2-7] 서비스 이름 중복 검증

### 4.1 기존 API 검증 추가

**서비스 생성** `POST /api/businesses/{businessId}/services`
- 동일 매장 내 같은 이름(대소문자 무시) 서비스 존재 시:

```json
{
  "success": false,
  "error": {
    "code": "SV007",
    "message": "동일한 이름의 서비스가 이미 존재합니다: 커트"
  }
}
```

**서비스 수정** `PATCH /api/businesses/{businessId}/services/{id}`
- 이름 변경 시 중복 체크 (자기 자신 제외)
- 같은 이름 에러코드: `SV007`

### 4.2 별도 중복 확인 API (신규)

```
GET /api/businesses/{businessId}/services/check-name?name=커트&excludeId=5
```

**Query Parameters:**

| 파라미터 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| name | String | Y | 확인할 서비스 이름 |
| excludeId | Long | N | 수정 시 자기 자신 제외 |

**Response (200):**
```json
{
  "success": true,
  "data": {
    "duplicate": false
  }
}
```

### FE 연동 가이드

```javascript
// 서비스 폼에서 이름 입력 시 실시간 중복 체크 (debounce 300ms)
const checkServiceName = async (businessId, name, excludeId = null) => {
  const params = new URLSearchParams({ name });
  if (excludeId) params.append('excludeId', excludeId);

  const res = await api.get(`/businesses/${businessId}/services/check-name?${params}`);
  return res.data.duplicate; // true = 중복
};

// 저장 시 서버에서도 자동 검증됨 (에러코드: SV007)
```

## 5. [P2-8] VIP/단골 임계값 설정 API

### 5.1 설정 조회 (신규)

```
GET /api/businesses/{businessId}/settings/customer-tiers
```

**Response (200):**
```json
{
  "success": true,
  "data": {
    "regularThreshold": 3,
    "vipThreshold": 10,
    "vipBenefitDescription": "VIP 고객 10% 할인"
  }
}
```

**기본값 (설정 미변경 시):**
- regularThreshold: 3
- vipThreshold: 10
- vipBenefitDescription: ""

### 5.2 설정 저장 (신규)

```
PUT /api/businesses/{businessId}/settings/customer-tiers
```

**Request Body:**
```json
{
  "regularThreshold": 5,
  "vipThreshold": 15,
  "vipBenefitDescription": "VIP 고객 15% 할인"
}
```

**검증 규칙:**
- `regularThreshold` >= 1
- `vipThreshold` >= 1
- `vipThreshold` > `regularThreshold` (VIP 임계값은 단골보다 커야 함)

**Response (200):**
```json
{
  "success": true,
  "data": {
    "regularThreshold": 5,
    "vipThreshold": 15,
    "vipBenefitDescription": "VIP 고객 15% 할인"
  }
}
```

### 5.3 자동 태그 연동

설정 변경 시, **이후 예약 완료 시점**부터 새 임계값이 적용됩니다.

- 예약 완료 -> `CustomerService.updateVisitStats()` -> 매장 설정 조회 -> 임계값 기반 자동 태그 생성
- 기존 고객의 태그는 다음 예약 완료 시 자동 갱신

### FE 연동 가이드

```javascript
// 매장 설정 페이지에서 고객 등급 기준 조회
const getTierSettings = async (businessId) => {
  const res = await api.get(`/businesses/${businessId}/settings/customer-tiers`);
  return res.data; // { regularThreshold, vipThreshold, vipBenefitDescription }
};

// 저장
const updateTierSettings = async (businessId, settings) => {
  const res = await api.put(`/businesses/${businessId}/settings/customer-tiers`, settings);
  return res.data;
};
```
