# 백엔드 요청사항 - Booking 서비스 개선

> **작성일:** 2026-02-21
> **작성 배경:** 프론트엔드 Booking(슬러그) 서비스 대규모 개선에 따른 백엔드 연동 요청

---

## 1. [필수] 예약 조회 API - 이름+전화번호 기반 조회

### 현재 상태
- `GET /api/public/reservations/{reservationNumber}?phone={phone}` 만 지원
- 예약번호를 기억하는 고객이 거의 없어 사용성이 떨어짐

### 요청사항
**새로운 API 엔드포인트 추가:**

```
GET /api/public/reservations/lookup?name={name}&phone={phone}
```

**요청 파라미터:**
| 파라미터 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| name | String | Y | 예약 시 입력한 고객 이름 |
| phone | String | Y | 예약 시 입력한 전화번호 |

**응답:** 기존 예약 조회 응답과 동일한 형식

**주의사항:**
- 동일 이름+전화번호로 여러 예약이 있을 수 있으므로, **가장 최근 예약** 또는 **목록 반환** 고려
- 목록 반환 시 프론트에서 선택 UI 제공 가능
- 완료/취소된 예약도 포함할지 정책 결정 필요

## 2. [필수] 고객 OAuth 로그인 - 네이버/구글 추가

### 현재 상태
- 카카오 OAuth만 고객 로그인으로 동작
- 관리자용 OAuth(카카오/네이버/구글)는 이미 구현 완료

### 요청사항
고객(Customer) OAuth 로그인에 **네이버, 구글** 추가

**기존 패턴 참고:**
```
GET /oauth2/authorize/kakao?loginType=customer    # 기존
GET /oauth2/authorize/naver?loginType=customer    # 추가 필요
GET /oauth2/authorize/google?loginType=customer   # 추가 필요
```

**콜백 응답 형식 (기존과 동일):**
```
/oauth2-redirect?accessToken=...&refreshToken=...&isNewUser=true&loginType=customer
```

**확인 필요:**
- `application.yml`에 네이버/구글 OAuth 클라이언트 설정이 `loginType=customer`에서도 동작하는지
- 고객 소셜 로그인 시 CUSTOMER 역할이 정상 부여되는지
- 기존 관리자 계정으로 고객 로그인 시 역할 분리 정책

## 3. [필수] 고객 프로필 API 403 오류 수정

### 현재 상태
```json
{
    "timestamp": "2026-02-20T16:07:30.469Z",
    "status": 403,
    "error": "Forbidden",
    "path": "/api/customer/profile"
}
```
카카오 로그인 직후 프로필 조회에서 403 발생

### 예상 원인
1. Spring Security 설정에서 `/api/customer/**` 엔드포인트의 권한 설정 문제
2. OAuth2 로그인으로 발급된 JWT에 CUSTOMER 역할이 포함되지 않는 문제
3. SecurityConfig의 `authorizeHttpRequests` 설정에서 customer 경로 누락

### 요청사항
- `/api/customer/**` 엔드포인트가 CUSTOMER 역할의 JWT로 접근 가능하도록 Security 설정 확인
- 신규 고객(isNewUser=true)의 경우에도 프로필 조회/수정이 가능해야 함
- 오류 발생 시 적절한 에러 코드 반환 (403 대신 CP001~CP004 등)

## 4. [필수] 영업시간 API 응답 형식 확인

### 현재 상태
매장 상세 페이지에서 영업시간이 모두 "휴무"로 표시됨

### 프론트엔드 기대 형식
```json
{
  "businessHours": {
    "mon": { "open": "09:00", "close": "18:00" },
    "tue": { "open": "09:00", "close": "18:00" },
    "wed": null,
    "thu": { "open": "09:00", "close": "18:00" },
    "fri": { "open": "09:00", "close": "18:00" },
    "sat": { "open": "10:00", "close": "15:00" },
    "sun": null
  }
}
```

또는 배열 형식도 지원:
```json
{
  "businessHours": [
    { "dayOfWeek": "MON", "openTime": "09:00", "closeTime": "18:00" },
    { "dayOfWeek": "TUE", "openTime": "09:00", "closeTime": "18:00" }
  ]
}
```

### 요청사항
- `GET /api/public/businesses/{slug}` 응답에 `businessHours` 필드가 포함되는지 확인
- 위 두 가지 형식 중 어떤 형식으로 반환되는지 확인
- 프론트에서 양쪽 형식 모두 파싱하도록 수정 완료했으나, 실제 응답 형식 확인 필요

## 5. [필수] 영업시간 저장 시 매장 이미지 보존

### 현재 상태
관리자에서 영업시간을 저장하면 매장 프로필 이미지가 사라지는 현상 발생

### 원인 분석
`PATCH /api/businesses/{businessId}` 호출 시 `businessHours`만 전달하면 다른 필드가 null로 덮어쓰기 됨

### 프론트엔드 조치 (완료)
- 영업시간 저장 시 기존 매장 데이터(name, phone, address, profileImageUrl 등)를 함께 전송하도록 수정

### 백엔드 요청
- **PATCH 엔드포인트가 전달된 필드만 업데이트하도록** 변경 (전달되지 않은 필드는 기존값 유지)
- 또는 영업시간 전용 API 분리: `PATCH /api/businesses/{businessId}/hours`

## 7. [권장] 주소 저장 시 좌표 정보 처리

### 현재 상태
- 프론트에서 카카오 주소검색 API(Daum Postcode) 연동 완료
- 도로명 주소, 우편번호를 선택하여 저장 가능

### 요청사항
비즈니스 정보에 다음 필드 추가:

| 필드 | 타입 | 설명 |
|------|------|------|
| addressDetail | String | 상세주소 (건물명, 호수 등) |
| zipCode | String | 우편번호 |
| latitude | Double | 위도 (Geocoding) |
| longitude | Double | 경도 (Geocoding) |

**좌표 변환 방안:**
1. **백엔드 처리 (권장):** 주소 저장 시 Kakao Geocoding API로 좌표 변환 후 저장
   - API: `GET https://dapi.kakao.com/v2/local/search/address.json?query={address}`
   - Header: `Authorization: KakaoAK {REST_API_KEY}`
2. 프론트에서 좌표를 함께 전달하는 방법도 가능하나, API 키 노출 문제

**좌표 활용:**
- `GET /api/public/businesses` 검색 시 위치 기반 정렬/필터 가능
- 향후 "내 주변 매장 찾기" 기능에 활용

## 8. [권장] 매장 검색 API 개선

### 현재 상태
- `GET /api/public/businesses?keyword=...&businessType=...&sort=...&page=...&size=...`

### 요청사항
응답에 다음 필드가 포함되는지 확인:

| 필드 | 설명 | 용도 |
|------|------|------|
| slug | 매장 슬러그 | 상세 페이지 이동 (필수!) |
| open | 현재 영업중 여부 | 영업중/종료 배지 |
| todayHours | 오늘 영업시간 문자열 | "09:00 - 18:00" |
| averageRating | 평균 평점 | 별점 표시 |
| reviewCount | 리뷰 수 | 리뷰 수 표시 |

**특히 `slug` 필드가 필수입니다.** 현재 검색 결과에서 slug가 null이면 카드 클릭/예약 기능이 동작하지 않습니다.
